# Requirements / Verification Traceability Matrix

状态：**LD6 完成（本机软件追踪完成；物理/Orange Pi 验证未运行）**
基线：Runtime implementation HEAD `28bf3eb`
矩阵日期：2026-08-21

本文是当前 Current Gate 的 LD6 产物。它只追踪已经存在的需求、合同、实现、测试、事故演练和
原始证据；它不增加 Runtime control authority，也不把文档链接当作执行证据。

## 证据与状态规则

- `VERIFIED / LOCAL SOFTWARE`：当前 HEAD 的源码与测试路径覆盖，且有本机运行证据；不表示
  Orange Pi、物理 CAN/RS-485、硬实时或功能安全。
- `VERIFIED / LOCAL LOOPBACK`：临时 prefix、localhost 或 vcan/模拟器路径通过；仍不是物理
  acceptance。
- `PARTIAL / NOT_RUN`：设计边界或局部错误路径已有证据，但需求要求的 Platform/真实网络场景
  没有 V1 实现或没有被授权执行。
- raw evidence 目录按仓库策略被 `.gitignore` 保护；链接在有本机 evidence 时可直接复核，仓库
  跟踪的 [`evidence/ld5_incidents/README.md`](../evidence/ld5_incidents/README.md) 说明其
  `LOCAL / VCAN / LOOPBACK / DIRTY` 分类。

## Open gaps and non-claims

1. `REQ-003` 保持 `PARTIAL / NOT_RUN`：Platform/Edge Agent 是 deferred，现有 remote loopback 不能替代真实跨主机失败场景。
2. 五项本机已验证需求的 raw evidence 仍是 `DIRTY`；这不降低源码/测试追踪，但不能写成 clean release、Orange Pi 或 physical acceptance。
3. physical CAN、`/dev/ttyS7`、MR0、STM32 reset/timeout、真实 systemd restart、掉电回滚和硬实时均不在本矩阵的 PASS 范围。
4. 当前实现没有新增 `ITransport`、Platform authority、health socket、第二个 CAN fd owner 或 Runtime C++ 重构。
